# CS-Scout 已知问题与修复记录

本文件记录已经确认的问题及其修复状态。用户身份、日志、Token 和本机路径不应写入本文件。

## WIN-5E-001：5E 未开放 CDP 时，退出后不一定自动恢复

- **状态**：已在 `v2.1.1-alpha.4` 修复
- **影响版本**：截至 `v2.1.1-alpha.3`
- **现象**：5E 已经以普通方式运行且没有开放自动侦察端口时，页面提示用户完全退出 5E。大多数情况下 CS-Scout 会在退出后重新启动 5E，但如果前一次就是由 CS-Scout 启动且 CDP 启动失败，退出后可能停在“上次未能启动”，需要重新进入一次自动模式。
- **根因**：监视器把前一次由 CS-Scout 发起但未建立 CDP 的启动记录为 `_last_launch_failed`。检测到 5E 已退出后，这个状态会阻止自动重试，与“随后自动启动”的页面文案不完全一致。
- **当前临时处理**：完全退出 5E（包括托盘和后台进程），切到“手动”再切回“自动”，让 CS-Scout 重新发起启动；仍失败时暂时使用 5E 手动模式。
- **修复要求**：
  1. 用户完全退出无 CDP 的 5E 后，监视器应自动进行一次新的受控启动，不要求切换模式。
  2. 重试必须有退避和次数限制，不能反复弹出 UAC 或形成启动循环。
  3. 不强制结束用户已经运行的 5E 进程。
  4. 页面状态应区分“等待用户退出”“正在重新启动”“重试失败”。
  5. 增加“已有普通 5E → 用户退出 → 自动重启成功”和“重试失败后可恢复”的离线状态机测试。
- **修复结果**：退出后先进入短暂退避，再自动重启一次；若新的客户端仍未开放 CDP，则停止
  自动重试并保留手动模式入口。重新进入自动模式或重新选择 5E 后可再次尝试。

## WIN-INSTALL-001：内置 Administrator 账号无法安装或启动

- **状态**：已在 `v2.1.1-alpha.4` 修复
- **影响版本**：截至 `v2.1.1-alpha.3`
- **用户反馈**：普通双击安装器仍提示不要使用管理员身份；从 Win+R 打开 CMD 再拖入安装器也无效。反馈机器只有 `Administrator` 一个 Windows 用户。
- **现象**：`Install-CS-Scout.ps1` 和 `Start-CS-Scout.ps1` 都通过 `WindowsPrincipal.IsInRole(Administrator)` 判断当前进程，只要返回 `true` 就直接退出。内置 `Administrator`、关闭管理员审批模式的系统，或始终使用完整管理员令牌的环境，即使普通双击也会命中该限制。
- **根因**：当前检查把“用户手动提权运行”和“当前 Windows 会话天生只有完整管理员令牌”视为同一种情况。Win+R、普通 CMD 和双击通常继承同一个令牌，因此换入口不能解决。
- **当前安全处理**：建议新建一个普通 Windows 用户，在该用户下重新解压、安装并运行 CS-Scout。不要修改脚本删除检查，也不要从来路不明的命令绕过；安装器和启动器目前都会阻止这种环境。
- **修复要求**：
  1. 区分普通管理员账户的主动提权、内置 `Administrator`（SID RID 500）和关闭 UAC/管理员审批模式等情况。
  2. 普通用户误用“以管理员身份运行”时仍应阻止，并给出准确中文说明。
  3. 对只有内置 `Administrator` 的机器提供明确、审计友好的兼容路径；不能仅删除管理员检查。可评估受约束的显式确认参数，或在路径、所有者、回环监听和数据目录检查通过后允许当前账号继续。
  4. 安装与运行始终使用当前登录账号的 `%LOCALAPPDATA%\CS-Scout`，不得写入其他用户的配置目录。
  5. 增加标准用户、过滤后的管理员令牌、主动提升令牌、内置 Administrator/关闭审批模式四类测试或可重复验证脚本。
  6. 玩家文档应说明真正可行的临时方案，不再建议 Win+R/CMD 作为降权方式。
- **修复结果**：安装器和启动器共用 Windows 令牌分类器。普通账号主动“以管理员身份运行”
  仍会被拦截；内置 Administrator 和关闭 UAC/审批模式产生的默认完整令牌会显示警告后继续，
  数据目录仍固定为当前登录账号的 `%LOCALAPPDATA%\CS-Scout`。
